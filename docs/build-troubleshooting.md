# Разбор: сборка и запуск на устройстве

Две проблемы, всплывшие при первой попытке собрать приложение и поставить его на телефон (28.08.2026). Обе разобраны по симптом → доказательства → причина → починка.

---

## 1. EAS Build падает на `npm ci`

**Симптом.** Три сборки подряд умирают на фазе `Install dependencies`, сообщение одно и то же:

```
npm error `npm ci` can only install packages when your package.json and
npm error package-lock.json or npm-shrinkwrap.json are in sync.
npm error Missing: typescript@5.9.3 from lock file
```

**Что сбивало с толку.** Строки `5.9.3` в `package-lock.json` нет вообще, а локально `npm ci --dry-run` проходит без единой жалобы.

**Доказательства, собранные по порядку:**

| Проверка | Результат | Вывод |
|---|---|---|
| `eas build:inspect -s archive` | в архив уходит актуальный лок, `5.9.3` = 0 вхождений | облако получает правильные файлы, гипотеза «уехал старый коммит» мертва |
| чистый пересбор: снести `node_modules` + лок, `npm install` | `5.9.3` по-прежнему 0 | дело не в инкрементальных установках |
| `npm install --package-lock-only --os=linux --cpu=x64` | лок побайтово тот же | дело не в платформе |
| `npx npm@10 ci --dry-run --include=dev` | **та же ошибка локально** | причина найдена |

**Причина.** Разные мажоры npm строят разное дерево. Лок писал npm 11.16 (локальный Node 24), а образ EAS собирал на npm 10. npm 10 добавляет ребро `typescript@5.9.3` — оно приходит из `devDependencies` пакетов `react-native-reanimated`, `react-native-unistyles`, `react-native-worklets`, — а npm 11 такого ребра не создаёт. Лок от npm 11 для npm 10 неполон, `npm ci` отказывает.

**Починка, два слоя:**

1. Разовая разблокировка — пересобрать лок десяткой: `npx -y npm@10 install --package-lock-only`. Такой лок принимают обе версии (проверено: `npm ci --dry-run` даёт `exit=0` и на npm 10, и на npm 11).
2. Постоянная — прибить версию Node в [eas.json](../eas.json):

```json
"build": {
  "base": { "node": "24.18.0" },
  "preview": { "extends": "base", ... }
}
```

Теперь облако собирает тем же npm 11, что и локальная машина. **Без второго слоя грабли возвращаются:** любой локальный `npm install` перепишет лок в формат npm 11 и следующая сборка снова упадёт.

**Урок.** `npm ci --dry-run` на своей машине ничего не доказывает про CI, если версии npm разные. Воспроизводить нужно той версией, что стоит в образе.

## 2. Приложение виснет на спиннере при старте

**Симптом.** APK ставится, запускается, но экран остаётся чёрным с крутящимся индикатором. Бесконечно.

**Доказательства:**

- `adb logcat -s ReactNativeJS:V` — только `Running "main"` и предупреждение GoTrue. Ни исключений, ни `log.fail` (он в [lib/log.ts](../src/lib/log.ts) пишется всегда, не только в DEV). Значит JS живой и ни один write не падал.
- `adb shell pm clear` — не помогло, старая локальная БД со снятой колонкой `photos` ни при чём.
- Скриншот через `adb exec-out screencap` — чёрный фон и маленький спиннер по центру. Это **не** splash: splash у нас `#208AEF` с картинкой. Чёрный фон = `theme.colors.background` тёмной темы, спиннер = `ActivityIndicator`.
- `ActivityIndicator` во всём проекте всего в трёх местах: `invite/[token]`, `recipe/[token]` и плитка фото. Первые два — центрированный спиннер на `theme.colors.background`, совпадение точное.

**Причина.** В [_layout.tsx](../src/app/_layout.tsx) deep-link роуты были объявлены **первыми** в `<Stack>`:

```tsx
<Stack ...>
  <Stack.Screen name="invite/[token]" />   // ← стал initial route
  <Stack.Screen name="recipe/[token]" />
  <Stack.Protected guard={!!session}>
    <Stack.Screen name="(tabs)" />
```

Начальный экран стека в expo-router — первый объявленный, если не задан `initialRouteName`. Приложение стартовало на `invite/[token]` без параметра `token` и залипало на его спиннере, вместо `(tabs)` / `sign-in`.

Объявлены первыми они были намеренно — чтобы не попасть под `Stack.Protected` и открываться без сессии. Но незадекларированные файловые роуты и так вне гардов, декларация была лишней.

**Починка.** Обе строки закомментированы. Роуты продолжают работать: expo-router регистрирует их по файлам.

**Статус: ⬜ не подтверждено.** Правка прошла `tsc`, но на устройстве ещё не проверена — идёт локальная debug-сборка.

**Урок.** В release-сборке `console.log` вырезан (`__DEV__` в `log.ts`), диагностировать нечем. Скриншот с устройства дал больше, чем логи: по цвету фона и форме индикатора экран опознаётся однозначно. Для отладки на устройстве быстрее ставить debug-сборку через `npx expo run:android --device SM_S921B`, чем гонять облачные сборки по 30 минут.

## Мелочи, попавшиеся по дороге

- **Supabase CLI 2.x не логинится на Windows.** `supabase login` — сегфолт Bun: CLI собран bun-ом в single-file exe (`supabase.exe` 98 МБ с рантаймом Bun 1.4.0 внутри), падает интерактивный TUI. `--version` и `--help` живые. Обход — `SUPABASE_ACCESS_TOKEN` и без интерактивного входа; в итоге миграции применялись руками через SQL Editor.
- **Эмулятор не стартовал:** `unknown skin name 'pixel_8'`. В `D:\android-avd\Pixel_8.avd\config.ini` поле `skin.path` вело на прежнее место SDK (`C:\Users\...\AppData\Local\Android\Sdk`), сам SDK лежит на `D:\Android\Sdk`. Поправлен путь.
- **Play Protect блокирует установку** APK, подписанного своим keystore. Кнопка «ОК» = отмена, ставить через «Все равно установить». Обновление поверх сборки с другой подписью невозможно — старую надо снести.
- **`RECORD_AUDIO` в [app.json](../app.json)** — приложение звук не пишет, при установке появляется лишний запрос микрофона. ⬜ Не убрано.

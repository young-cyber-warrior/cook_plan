## 1 
 - при создани рецепта в название катеогории для члена семьи видет как я понял ключ D:\projects\mobile\my-app\docs\photo_2026-09-06_09-16-18.jpg

### План
Причина: у каждого пользователя свой набор категорий (root-store засевает `DEFAULT_CATEGORIES` при первом входе), а `toCategories` (`src/stores/mappers.ts`) отбрасывает строки с чужим `owner_id`. Рецепт члена семьи ссылается на `category_id` строки владельца → `categoryLabel` не находит её и падает в fallback = сырой UUID.

Правки:
1. `toCategories` — схлопывать категории по `slug`, предпочитая свою строку. Дефолты (`breakfast`/`lunch`/`dinner`/`snack`) у всех членов семьи имеют одинаковый slug → в списке остаётся одна запись; кастомные категории (slug = uuid) уникальны и видны всем.
2. Новый маппер `canonicalCategoryIds(rows, categories)` — карта `id любой строки категории → id канонической`.
3. `toRecipe` принимает эту карту и нормализует `category_id`. Это чинит и подпись на карточке, и подсветку выбранной категории в `CategoryToggle` при редактировании общего рецепта.
4. `RecipesStore.recipes` / `saveRecipe` прокидывают карту.

Статус: сделано.

## 3
 - при добавлении рецетпа нет логики добавления фото она видна тольок потом когда после сохраения нажал редакттирвоать 

### План
Причина: `RecipePhotoEditor` работает через стор по `recipeId` (`photosOf` / `addPhoto`), а в шторке создания рецепта строки ещё нет. Писать фото «вперёд» рецепта нельзя: у `recipe_photos.recipe_id` FK, и в очереди аплоада фото уехало бы раньше рецепта.

Решение: черновик держит выбранные фото в памяти, а на сохранении стор одной операцией пишет рецепт и уже потом — фото.

Правки:
1. Новый презентационный `PhotoTiles` (плитки + «Из галереи»/«Снять»), без стора. `RecipePhotoEditor` переходит на него.
2. Хук `usePhotoPicker` — обёртка над `pickPhoto`/`capturePhoto` с `errors.notify` (закрывает пометку «где обработка ошибок» в этих файлах).
3. `useRecipeDraft`: `photos: PhotoSource[]`, `addPhoto`/`removePhoto`, очистка в `reset`.
4. `AddRecipeSheet`: блок «Фото» с `PhotoTiles`; `onSave(recipe, photos)`.
5. `RecipesStore.addRecipe(draft, photos)` — рецепт с ингредиентами и фото пишутся в одном `write`, последовательно: порядок в очереди аплоада гарантирован, `position` фото берётся из индекса. Общая часть вынесена в приватный `savePhoto`, `addPhoto` теперь через него.

Статус: сделано.

### Просмотр фото в рецепте
Коллаж живёт в шапке карточки, рядом с названием и категорией: новый `RecipePhotoCollage` (обёртка над `RecipeCollage` из карточки дня) читает фото из стора по `recipeId`. Тап по вееру открывает `PhotoViewer`, тап по остальной шапке — аккордеон: вложенный `Pressable` перехватывает жест сам. Статус: сделано.

### План
Причина: `expo-crypto@57.0.2` типизирует `digest(algorithm, data: BufferSource)`, но JS-обёртка отдаёт `data` в нативный модуль как есть, а Kotlin-сигнатура — `digest(algorithm, output: TypedArray, data: TypedArray)`. Конвертер Expo Modules принимает только `TypedArray`, сырой `ArrayBuffer` не конвертируется. TS-тип шире, чем поддерживает натив.

Правка: в `preparePhoto` передавать `new Uint8Array(data)`. Само поле `data` остаётся `ArrayBuffer` — `AttachmentQueue.saveFile` принимает `AttachmentData = ArrayBuffer | string`.

## 5
- проблема не видно поля ввода на стрице логина (все остальные места уже отфикшены здесь нужно доавить логику как сделано в других местах) 

### План
Причина: экран входа — обычный `View` с `justifyContent: 'center'`, клавиатура просто перекрывает поля. `KeyboardProvider` в `app/_layout.tsx` уже стоит, но сам экран ничего с клавиатурой не делает.

Правка: обернуть карточку в `KeyboardAwareScrollView` теми же пропсами, что и в `BottomSheet` (`mode="layout"`, `bottomOffset`, `keyboardShouldPersistTaps="handled"`). Центрирование и отступы переезжают в `contentContainerStyle` с `flexGrow: 1`, снизу добавляется `insets.bottom`.

Важно: `KeyboardAwareScrollView` — Reanimated-компонент, Unistyles-стили в него отдавать нельзя (`[Reanimated] Invalid value for "unistyles_…"`). Его стили собираются как в остальных Reanimated-местах проекта: статика через `RNStyleSheet.create`, тема и `insets` — инлайном в массиве. Отступы берутся из `useSafeAreaInsets()`, а не из `rt.insets`.

Статус: сделано.
